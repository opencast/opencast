Workflow variables containing a colon in the variable name can now be properly addressed by escaping the colon with a backslash. Beforehand, the variable syntax ${var:iable} would look for a workflow property called "var". If that cannot be found, the value "iable" would be used as default. Users can now use the syntax ${var\:iable} to look up the property "var:iable" instead. This is especially useful for workflow properties defined by analyze-mediapackage based on element tags, e.g. you can now address properties such as "captions_source_hastag_lang:en". Note that this is a breaking change in the sense that the string "\:" is now replaced in the variable name and the default value with a ":". We don't expect anybody is using "\:" in variable names at the moment. So this should not be breaking in practice.
