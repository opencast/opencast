Opencast now requires OpenSearch 2.x

The Elasticsearch/OpenSearch client Opencast uses internally was swapped from Elastic's own (deprecated) client to
OpenSearch's client, which is not wire-compatible with OpenSearch 1.x's predecessor lineage the same way. As a
result, OpenSearch 1.x is no longer supported; you must run OpenSearch 2.x.

Elasticsearch was previously supported as an alternative to OpenSearch, but that support has been dropped as of this
release.

This is an index change, though no index mappings were altered by this release. OpenSearch 2.x reports
`minimum_index_compatibility_version: 7.0.0`, which covers indices created by OpenSearch 1.x, and OpenSearch 2.x's
bundled Lucene version (9.x) is only one major version ahead of 1.x's (8.x), within Lucene's normal backward-read
compatibility window. Because of this, an in-place upgrade of the OpenSearch node should work directly, without
reindexing:

1. Back up your OpenSearch data directory.
2. Stop Opencast and the OpenSearch 1.x node.
3. Install OpenSearch 2.x against the same data directory, following OpenSearch's own upgrade instructions.
4. Reinstall the `analysis-icu` plugin if you installed it manually. Plugins are version-locked to the OpenSearch
   major version, so the 1.x build will not load on 2.x.
5. Start OpenSearch 2.x, confirm the cluster is healthy, then start Opencast again.

Note that the `docs/upgrade/20_to_21/update_index.sh` script does not apply to this change: it reindexes data from an
old index *mapping* to a new one on an already-running cluster, and this release doesn't change any mapping.

If you would rather not rely on OpenSearch's cross-version index compatibility, or want a clean rebuild for any other
reason, you can instead point Opencast at a fresh, empty OpenSearch 2.x installation and have it repopulate the index
from the database:

1. Install OpenSearch 2.x, either alongside the old 1.x node or by replacing it once you no longer need the old data.
2. Point Opencast's `org.opencastproject.elasticsearch.*` configuration keys at the new node.
3. Restart Opencast. Since the new node has no index yet, Opencast will create an empty one automatically.
4. Trigger a full index rebuild with an authenticated `POST` request to `/index/rebuild` on the admin node. This
   repopulates the index from the database and other backing services (series, scheduler, asset manager, comments,
   workflow, search), not from the old OpenSearch index. You can check progress with
   `GET /index/rebuild/states.json`.
5. Once the rebuild finishes, decommission the old OpenSearch node.
